# diff 模块

比较两段文本交给 Phorge：行级的 unified diff，与逐词逐字的 prose diff。

| | |
|---|---|
| 二进制 | `gorge-render`（与 render 域同进程） |
| 端口 | `:8140`（无独立端口，原 `:8130` 已废弃） |
| 包 | `go/internal/diff/`、`go/internal/diff/unified/`、`go/internal/diff/prose/` |
| 契约 | [`api/openapi/diff.yaml`](../../api/openapi/diff.yaml) |
| 固件 | `tests/contract/diff/`（unified 输出使用**字节精确**断言） |
| 兼容约束 | [`compat/phorge/README.md`](../../compat/phorge/README.md) 第 4 节 ← **改动前必读** |

## 1. 职责边界

**负责**：接收两段完整文本，返回 unified diff 文本或 prose 片段序列。

**不负责**：读文件、解析 diff、渲染 HTML。两个引擎都是纯函数,不碰 I/O。

**为什么没有独立进程。** 迁入前 `gorge-diff` 是自己的二进制,监听 `:8130`。合并进 `gorge-render` 是因为两个域都是无外部依赖的纯计算:没有数据库、没有缓存、没有下游服务,拆成两个容器只多一样要部署的东西,换不来任何隔离收益。路径按域命名(`/api/diff/*` 而非 `/api/render/*`)本来就是为了让这种合并不需要改动任何一侧,理由见 [`../architecture.md`](../architecture.md) 第 4.3 节。

一个 token 同时守两个域:它认证的是**调用方对这个进程**的身份,不是对某个路由分组的身份。

## 2. 路由与依赖

```go
func RegisterRoutes(app fiber.Router, deps *Deps) {
	g := app.Group("/api/diff")
	g.Use(auth.Token(deps.Token))

	g.Post("/generate", generateDiff(deps))
	g.Post("/prose", proseDiff(deps))
}
```

| 方法 | 路径 | 鉴权 |
|---|---|---|
| POST | `/api/diff/generate` | 需要 |
| POST | `/api/diff/prose` | 需要 |

`Deps` 只有两个字段(`Token` / `MaxBytes`)——比 render 的三字段少一个,因为两个引擎是无状态函数,没有引擎实例需要注入。

`TestRoutePathsAreStable` 断言这两条路径仍注册着;`TestRenderRoutesAreUntouched` 反向断言注册本域不会遮蔽 render 域的分组,这是两个域能共用一个进程的前提。

## 3. unified 引擎

### 3.1 这里的输出是被**解析**的,不是被渲染的

这是本模块与 render 域最重要的一处差异,决定了下面所有设计。

PHP 侧 `PhabricatorDifferenceEngine::generateRawDiffFromFileContent` 原先 `proc_open` 调 `diff -U65535 -L <name> -L <name>`,输出交给 `ArcanistDiffParser` 与 `DifferentialHunkParser`。所以本包要复现的不是「一份合法的 unified diff」,而是**GNU(以及 Apple/FreeBSD)diff 逐字节写出来的那一份**。

**偏离不会在任何地方报错。** 解析器接受一个错误的 hunk 头,然后静默地把它之后的每一行都放错位置——错误在代码评审页面上表现为渲染错位,离出错点已经很远。render 域的固件刻意只断言几个 CSS 类名(Chroma 的markup 随版本漂移,钉死没有意义);本域的固件反过来做**整值比对**,因为这里不存在「可以安全断言的子集」。

### 3.2 行模型:`(text, hasNewline)`

迁入前的实现把文本按 `\n` 切成 `[]string` 并丢掉尾部空元素,尾换行信息就此丢失。这不够,因为 **GNU diff 认为「无尾换行的一行」与「同样文字但有尾换行的一行」是不同的行**:

```go
type line struct {
	text       string
	hasNewline bool
}
```

两个字段都参与相等判定。于是 `"a\nb"` 对 `"a\nb\nc\n"` 会报 `-b` / `+b`,而不是把 `b` 当共享上下文保留——给文件补一个尾换行是真实变更,必须渲染成变更。

### 3.3 hunk 头的三种形态

全文上下文(`-U65535`)下每个 hunk 都从第 1 行开始,所以只有计数在变。但计数有三种写法,都不是装饰:

| 行数 | 写法 | 为什么 |
|---|---|---|
| 0 | `0,0` | 空的一侧从 0 开始——没有「第 1 行」可指 |
| 1 | `1`(**省略计数**) | GNU 对单行侧完全省略 `,1` |
| ≥2 | `1,count` | 常规形态 |

写成 `-1,1` 而 GNU 写 `-1`,足以让整个 hunk 错位。`formatRange()` 就这三个分支。

### 3.4 `\ No newline at end of file` 的落点

标记跟在**承载那个无尾换行行的记录**之后。一条规则推出三种可观察情形:

- 两侧共享的末行都缺尾换行 → 标记出现一次(跟在上下文行后)
- `-`/`+` 配对且两侧都缺 → 出现两次,各自一处
- 只有一侧缺 → 出现在那一侧的位置

注意 diff 文本自身的每一行(包括标记行)都以换行结尾——**缺尾换行的是被描述的内容,不是 diff**。

### 3.5 identical 分支刻意**不**与 GNU 对齐

这是全包唯一一处以 PHP 而非 GNU 为基准的地方。

`diff` 在两个文件相同时退出码 0 且什么都不输出。PHP 侧因此在这一支自己拼字符串,好让调用方仍能据此渲染那个未变更的文件——它手里没有第二份内容。那个合成串就是 `ArcanistDiffParser` 一直以来收到的东西,所以它的字面行为(连怪癖一起)才是契约:

| 怪癖 | 后果 |
|---|---|
| `explode("\n", …)` 不丢尾部空元素 | `"a\nb\n"` 算 **3** 行,末行渲染成一个空格 |
| 计数硬编码为 `-1,{len} +1,{len}` | 保留了 GNU 会省略的 `,1` |
| 空输入仍 explode 出一个元素 | 得到一行 hunk,而非只有文件头 |

所以 `Old` 与 `New` 都为空时返回的是 `@@ -1,1 +1,1 @@` 加一个空格行,而不是空字符串。**不要「顺手修正」成 GNU 的行为。**

### 3.6 LCS,以及它与 GNU 的一处不等

经典 LCS 动态规划,`O(n*m)` 时空。回溯时**平局优先 insert**,这才让被替换的行以 `-old` 先于 `+new` 的顺序出来——GNU 的顺序,也是 hunk 解析器期望的顺序。

**但对齐的选择本身不与 GNU 全等。** 一行重复出现时可能存在多个同样最小的对齐,GNU 的选择来自 Myers 加边界平移启发式,本包不复现。约 2900 组生成输入实测:91.4% 逐字节一致,8.6% 分歧且全部发生在含重复行的输入上,而 **hunk 头 0 次不同、编辑数 0 次不同**。

所以保证是分层的:

| | 保证 |
|---|---|
| 文件头、hunk 头计数、`\ No newline` 位置 | 与 GNU **逐字节等同** |
| 编辑脚本的规模 | 始终**最小** |
| 歧义时选中哪一个对齐 | **不保证**与 GNU 相同 |

这个边界可以接受,是因为会静默造成损害的失败模式是 hunk 头算错——那会让下游把之后每一行都放错位置——而它实测 0 次不同。对齐不同只是高亮了另一组同样合法的行。根治要换 Myers,与第 5 节那道内存护栏是同一个改动,见 [`../findings.md`](../findings.md) 第 5 条。

GNU 用的 Myers `O(ND)` 算法也没有本包的单元数上限,这是同一处技术债的两个症状。

### 3.7 期望值的来处

固件与单元测试里的期望字符串**不是手写的**,是从真实二进制抓的:

```
printf '<old>' > a; printf '<new>' > b
diff -U65535 -L 'a 9999-99-99' -L 'b 9999-99-99' a b
```

哪条开始失败,先重跑这条命令再动期望值。

更省事的是 `systemdiff_test.go`:它每次 `go test` 都真的去调系统 `diff` 做交叉验证,不依赖谁记得重跑命令。上面那处 GNU 不等就是它测出来的,手写用例没覆盖到。`diff` 不在 PATH 时它 skip 而非失败。

## 4. prose 引擎

### 4.1 四级递归

```
段落 (\n+) ──► 句子 ([\n,!;?.]+) ──► 词 (\s+) ──► 字符 (rune)
```

只有**真正变更的区域**才下降到下一级。未变更的段落比较一次(按哈希)就再也不看,这是开销可控的原因。反过来,直接在全文上跑字符级既是平方复杂度,输出也难读——它会在无关的词之间找到偶然的单字符匹配。

各级算法的选择不是随意的:

| 级别 | 算法 | 为什么 |
|---|---|---|
| 段落 | `hashDiff` 贪心前向匹配 | 段落数少但每段长。相等判定廉价且几乎总是决定性的,而在段落上跑编辑距离矩阵要付 `O(n*m)` 次字符串比较,换不来更好的对齐 |
| 句子 / 词 / 字符 | `editDistanceDiff` 编辑距离 | 片段多而短,需要真正的对齐 |

`hashDiff` 的匹配是**贪心且只向前**的:一个片段只能与游标处或之后的第一个未被认领的相同片段配对,绝不回头。这保证对齐单调,也正是「两个互换位置的段落不会被报成未变更」的原因。

### 4.2 唯一的硬不变量:无损

prose 输出没有外部基准可比(Phorge 把这些片段渲染成 markup,不会再解析回去),所以要守的是**无损**:

> `=` 与 `-` 拼起来精确还原旧文本,`=` 与 `+` 拼起来精确还原新文本。

引擎里每一处切分都保留分隔符正是为此——正则用捕获组 `(...)`,`stitchPieces` 再把分隔符缝回去。丢一个或多一个分隔符,在渲染出的 diff 里是看不见的,文本只是读起来稍微不对。`TestSegmentsReconstructBothTexts` 用 17 组输入压这一条。

### 4.3 smooth:句子级不做,更细的级别做

`smooth()` 把两侧都是变更的孤立 `s`(相同)改写成 `x`(替换),让整段读作一次替换而不是三个碎片。

只在词级与字符级生效。句子足够大,夹在两处变更之间的一个未变更句子值得如实报成未变更;词和字符不是——两次编辑之间一个孤零零的共享字母是噪声,折进周围的变更里更好。

### 4.4 combineRuns:只提**布局字符**

合并删除段与插入段时,两侧共享的前后缀会被提成 `=`。但只有布局字符够格:空白、句读、括号。

这个限制就是这个函数的要点。提取任意公共前缀会**断言那部分在编辑中存活了**——`"abcX"` → `"abcY"` 会渲染成未变更的 `abc` 加一个单字母变更,而诚实的读法是整个 token 被替换了。空格或逗号不承载这种含义,不高亮它只是去掉噪声。

## 5. 三道护栏

| 层级 | 阈值 | 检查点 | 报什么 |
|---|---|---|---|
| 域级字节数 | `GORGE_DIFF_MAX_BYTES`,默认 1 MiB | handler 内 | 413 `ERR_TOO_LARGE` |
| 传输层 body | 2 M(`httpx` 硬编码) | 中间件 | 413 `ERR_TOO_LARGE` |
| LCS 表单元数 | 4,000,000(编译期常量) | 切完行之后 | 413 `ERR_TOO_LARGE` |

三条都报同一个码,调用方不必区分——补救动作都是「少发一点」。

**域级检查的是 `len(Old) + len(New)` 之和**,不是任一侧。diff 的开销由两侧共同决定,所以两个 600 KiB 的文件加起来是超限的。默认值刻意压在传输层 2M 之下,好让越界请求被**知道自己量了什么**的那道挡下,而不是被中间件挡下。

**第三道不能被前两道替代。** LCS 表分配的是 `n*m`,不是行数:2001 行对 2001 行只有几十 KB,却要一张四百万单元的表(64 位下 32MB 的 `int`);而 100 行对 100000 行反而便宜,必须放过。所以上限压在**乘积**上,判定写成 `n > maxCells/m` 的除法形式——因为溢出的正是 `n*m`。`TestTooManyCellsIsRejectedButSkewIsNot` 同时压住这两半。

## 6. 配置

| 变量 | 兜底旧名 | 默认值 | 说明 |
|---|---|---|---|
| `GORGE_DIFF_MAX_BYTES` | **无** | `1048576` | `len(old)+len(new)` 上限(字节) |

**这一条没有旧名兜底,是全仓库的例外。** 迁入前的服务读 `MAX_BODY_SIZE`,但那是个 Echo 传输层限制、值是字符串(`"10M"`)、作用于整个请求体;`GORGE_DIFF_MAX_BYTES` 是字节数、作用于 `len(old)+len(new)`。认旧名会**静默地重新解释它的值**,所以这是一次重命名而非兜底。

`diff.Config` 刻意**不嵌** `config.Base`:监听地址与 service token 属于进程,而进程同时服务 render 域,两个域各自声称拥有 `GORGE_LISTEN_ADDR` 会让「谁说了算」变得含混。当前由 `render.Config` 持有 `config.Base`,这一点记在 [`../findings.md`](../findings.md)。

## 7. 本域没有域级错误码

值得明写,因为 render 域有一个(`ERR_HIGHLIGHT_FAILED`)。

两个引擎都没有可报告的失败模式:prose 引擎是全函数;unified 引擎唯一会拒绝的是「大到没法 diff 的输入」,而那已经是平台码 `ERR_TOO_LARGE` 了。在这里造一个码,它永远不会被返回。

将来真的需要时,加在 `go/internal/diff/http.go` 里,**不要塞进 `platform/httpx`**。

## 8. 两个 handler 共享检查带来的一处陷阱

`bind()` 与 `checkSize()` 返回 `(answered bool, err error)` 两个值,调用方必须按 `answered` 分支,**不能按 error 分支**。

`httpx.Fail` 写完响应后通常返回 `nil`，因此 helper 的 `nil` 无法区分「继续」与「已经答复了」。当成前者，就会给一个已经写完的响应追加第二个 JSON 文档，而**任何只看状态码的测试都发现不了**。迁入过程中这个 bug 真实发生过一次，是 diff 契约固件——它整体解析响应体——抓到的，`decodeSoleEnvelope` 现在守着它。

render 域把同样三道检查内联在它那个 handler 里,`return httpx.Fail(...)` 自己就终止了流程,问题根本不会出现。本域两个端点共享这些检查,才需要这个额外返回值。
